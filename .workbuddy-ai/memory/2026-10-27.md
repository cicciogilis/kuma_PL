## Programmazioni — complementari editabili + rifiniture

### TRAPPOLA: `<button>` è `border-box`, `<div>` no
Convertendo l'header del giorno complementari da `<button>` a `<div role="button">`
(serviva per mettere matita e cestino dentro la riga, non si possono annidare
button) il riquadro è sbordato di 22px: `width: 100%` + `padding: 9px 10px` +
`border: 1px` in `content-box`. Il progetto **non ha** un `* { box-sizing: border-box }`
globale (solo `body`/`.app` e pochi altri), e i `<button>` sono border-box per
default UA: il bug si vede solo sui div.
→ `box-sizing: border-box` aggiunto a `.program-week-toggle`.

### Righe grigie e allineamento
`.program-accessory-day` aveva `padding-left: 10px; border-left: 2px solid #333`:
era quella la "riga grigia" che rendeva il giorno più stretto e spostato a destra
rispetto all'header "Complementari". Rimossa; `gap` 8 → 10 come `.program-week`.
Verificato in app: giorno 318px = header 318px, stesso `x` e stesso `right`.

### Header del giorno su mobile
Con due icone in più non ci sta su una riga a ≤480px. Regola:
```css
@media (max-width: 480px) {
  .program-accessory-day-toggle { flex-wrap: wrap; gap: 6px; }
  .program-accessory-day-title { flex: 1 1 100%; }   /* titolo su riga 1 */
  .program-accessory-day-toggle .program-week-chevron { margin-left: auto; }
}
@media (max-width: 400px) { .program-accessory-day-order { display: none; } }
```
Senza il `flex: 1 1 100%` il wrap naturale spostava la chevron da sola su una
terza riga a 320px.

`accessoryNoteKeyFor(day, exerciseIndex)` = `accessory-{day}-{index}`.

criterio (indice+1).

### TRAPPOLA: angoli retti della scheda compressa
`.program-card` ha `border-radius: 10px` ma **overflow: visible** (serve per
lasciare sticky l'intestazione della tabella). `.program-card-header` ha
`background-color: #222` con `border-radius: 9px 9px 0 0` → angoli inferiori
**retti**.
- **Espansa**: il `.program-card-body` è trasparente, si vede il fondo arrotondato
  `#1a1a1a` della card → angoli giusti.
- **Compressa**: l'header *è* tutta la card, il suo `#222` opaco copre la curva
  del bordo → angoli **retti** in basso a sinistra/destra.
→ Aggiunta la regola `.program-card:not(.expanded) .program-card-header
  { border-radius: 9px; }` (9px = 10px della card − 1px di bordo, come gli
  angoli superiori già facevano). Stessa modifica in SBD-ladder.

**Verifica oggettiva (non a occhio)**: il trucco è il colore di pagina
"rumoroso" (magenta) nella fixture + campionamento del PNG via canvas in-page
(`page.screenshot({clip})` → `Image` → `getImageData`). Se l'angolo è smussato
si vede il magenta del page, se è retto si vede il grigio `#222` dell'header.
Con il fix: compressa ed espansa restituiscono entrambe magenta sull'angolo.
Test: `.workbuddy-ai/tests/cardCorners.e2e.mjs` + `cardCorners.fixture.html`.

**Attenzione al clip delle screenshot**: se la card è più alta del viewport,
`page.screenshot({clip})` ritaglia il bordo INFERIORE della pagina, non della
card (i pixel risultano del bordo/margine). Per campionare il fondo della card
serve `fullPage: true` **insieme** a `clip`.

Verificato in app reale: `.workbuddy-ai/tests/cardCornersReal.e2e.mjs` (6 assert,
angolo = page #000) e `cardCornersExpanded.e2e.mjs` (5 assert, la card espesa
NON cambia: header resta `9px 9px 0 0`, angoli sotto arrotondati).
